安装避坑指南

这些不是推测，是本站 2026-11-17/18 在隔离 profile 里真装 30+ 个插件踩出来的。

一、先分清两种安装源

来源命令什么时候用
npm 包dsh plugin --profile <prof> add 包名包在 npm 上且有正常发布版本
GitHub 仓库dsh plugin --profile <prof> add github:owner/reponpm 上找不到（返回 404）、或 npm 版本是占位包

实测：养鱼圈里 dsh-purge-community、dsh-purge-safe、dsh-liketavern、gal-view 都不在 npm，只能用 github: 装。装之前先在 npm 搜一下包名，搜不到就走 GitHub 源。

二、最坑的一种失败：坏包污染整个 profile

现象：你明明在装 A 插件，报错却指向 B（例如 dsh-purge-0.0.0-stage.tgz 的 tarball 截断）。而且之后同一 profile 装什么都失败。

原因：损坏的包被写进了该 profile 的 lockfile，之后每次 add 都会重试它。

  1. 先确认是哪个包坏了（看报错里的 tarball 文件名）
  2. 在该 profile 里移除它：dsh plugin --profile <prof> remove 坏包名
  3. 还不行就删掉该 profile 的 node_modules 与 pnpm-lock.yaml 后重装
  4. 最省事：换一个干净的 profile 重来

三、版本不兼容：别乱用 allow-version

安装器会拦下与当前 DSH 版本不匹配的插件（例如 billion-context-dsh@0.2.27 对 0.2.2-rc.3）。它会提示你可以用 allow-version 强制安装——那等于自己承担崩溃与数据丢失风险，本站不建议，除非你清楚自己在做什么。

四、GitHub 源装大仓库会超时（实测数据）

用 github:owner/repo 安装时，DSH 会先克隆仓库，速度取决于网络与仓库体积：

插件结果耗时
dsh-liketavern成功 0.5.12156 秒
dsh-purge（mmparko）成功 1.1.7172.8 秒
dsh-tavern（flizzywine）超时未完成> 30 分钟
gal-view超时未完成> 15 分钟

遇到超时不要急着判断"插件坏了"：先确认是不是网络问题（换个时间、换代理），再决定是否继续。本站把这类记为"超时未完成"，不写成"装不上"。

五、装上了但报失败：pnpm 拦截构建脚本

现象：+ 插件名 版本号 明明出现了，但命令最后以 ERR_PNPM_IGNORED_BUILDS 失败退出，提示 Ignored build scripts: protobufjs。

这不是装不上，而是 pnpm 11 默认不允许依赖执行构建脚本（安全策略）。实测三个插件（@michengai/dsh-im-connect、@tencent-connect/dsh-qqbot、dsh-session-superagent）都因此报了同一个错，但包其实已经落地 node_modules、也写进了 profile 的 dependencies——只是没进入 dsh.profile.bundles，所以不会生效。

本站把这种状态记为「半装」，不算通过、也不算失败。

我们试过的三种办法（都失败，如实记录）

  1. package.json 里加 pnpm.onlyBuiltDependencies —— pnpm 11 直接警告该字段已废弃、被忽略
  2. 写进 pnpm-workspace.yaml 的 onlyBuiltDependencies —— pnpm config get 确实能读到 ["protobufjs"]，但安装仍然报 ERR_PNPM_IGNORED_BUILDS
  3. 加 --config.onlyBuiltDependencies=protobufjs 显式传参 —— 同样被拦

结论：这个门只认**交互式**的 pnpm approve-builds（要人逐个确认），没法用配置脚本化绕过。所以本站这三个插件只能记「半装」，不写成成功。

你要用的话，在 profile 目录里跑 pnpm approve-builds，看清楚是哪个依赖要跑脚本、判断可信后再放行，然后重新 add 一次。

另一个坑：手改 profile 的 package.json 别带 BOM

实测：用 PowerShell 的 Set-Content -Encoding UTF8 写 package.json 会带 BOM，DSH 读取时直接 SyntaxError: Unexpected token ''，整个 profile 无法安装任何插件。用编辑器保存为「UTF-8 无 BOM」即可。

六、怎么确认"真的装上了"

  1. dsh --profile <prof> --dump-config 里能看到该插件的条目 = 已进入组合
  2. packages 在 node_modules 里但 dump-config 里没有 = 装了但没被组合（常见于独立 app 类插件）
  3. 启动后侧边栏/设置里没出现入口 = 它可能依赖 webServer 之类的服务，在精简 profile 里会 pending

七、测试插件请用独立 profile

别在每天用的 profile 里试装来源不明的插件。养成习惯：

dsh plugin --profile test-only add github:owner/repo

试完整个 profile 删掉即可，不影响你日常的会话与配置。

八、装完先做三件事

  • 看它要哪些权限/凭据（README 里的"风险提示""免责声明"章节）
  • 确认它是否会把内容发到第三方（本站每条核验都标了 🟢/🔴）
  • 试用时先跑一个不重要的会话，别直接上主号/主档案
