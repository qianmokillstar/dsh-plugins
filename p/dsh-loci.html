dsh-loci · 记忆宫殿（只放索引）

已核实 人工短评 风险 中 🟢 纯本地
一句话结论：它把"记忆"和"提示词"解耦——系统提示里只放一份索引（约 1.3k token、稳定），细节靠 loci_search / loci_get 按需推门；空库时注入 0 字节。

适合谁

  • 被记忆插件"固定税"折磨过的人：每次请求都多几 KB 系统提示，长期很贵。
  • 需要"列出全部"真的能列完、不静默截断的人。
  • 长线角色扮演：设定多但不想每轮全塞进上下文。

解决什么

  • 索引与内容分离：系统提示只放一行一条的索引（作者实测约 1.3k tokens，稳定）。
  • 检索工具：loci_search 返回 total 与 cursor；loci_get 取全文 + 历史 + 逐字证据。
  • 硬字节预算：100 条记忆时索引仍是同一段，超出会明确写"… 还有 N 条"。
  • 前缀缓存友好：只读回合段内容逐字节不变。
  • 空库注入 0 字节，没有标题、没有说明。

风险点

  • 作者在 README 里点名对比了其它插件（mnemon"系统提示 +4.8KB、16 个工具"、ledger-memory 无界增长、某些插件静默截断召回）。这些是作者自述，我们未逐一复验，看你自己的场景。
  • 索引只放"一行一条"，摘要质量取决于你怎么写索引；写不好就等于检索不到。
  • 依赖模型主动调用 loci_search——模型偷懒时不会自动召回（与"硬注入"型插件相反）。
  • 版本号从 6.x 到 7.x 跨度不大但迭代快，升级前看 CHANGELOG。

替代品

  • dsh-mnemon：分层记忆 + 回合记忆栏，可见性强但固定税更高。
  • dsh-fish-memory：会淡忘、命中才注入。
  • dsh-prime-memory：全自动蒸馏注入，不用模型主动查。
