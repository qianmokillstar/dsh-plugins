dsh-icon-library · 项目级图标库

已核实 人工短评 风险 低 🟢 纯本地
一句话结论：给"图标"建立语义身份——对话里写 <关闭>，人和 Agent 取到的是同一个图；数据存在项目根的 .icons.json 里，能 diff、能跟着仓库走。

适合谁

  • 前端项目里 SVG 散落在各组件、名字各写各的人。
  • 经常和 Agent 一起改 UI，受够"我说的图标"和"它用的图标"不是一个。
  • 想让图标资产可读、可 diff、可复用的团队。

解决什么

  • 语义指代：形状入库后获得名称、应用规则与稳定身份；icon_list / icon_get 按意取图，icon_annotate 回写使用经验。
  • 单一来源：名称、规则、图形同存于 .icons.json，按内容去重、改名级联，业务代码不用 import。
  • 多源入库：粘贴 SVG、从 Iconify / IconMCP 导入、扫描工作区把匿名形状收编命名、AI 生成。
  • 全局同步：同一语义身份贯穿代码引用（@asset 拷贝、派生指针），图形改一次全部跟随。

风险点

  • 会写项目文件：.icons.json 是新增的工程文件，团队要接受它进仓库。
  • 扫描工作区会读你的代码结构（本地行为，但项目大时耗时）。
  • 从 Iconify / IconMCP 导入图标要联网，图标授权仍按来源判断（很多图标库有署名要求）。
  • 让 Agent 参与"收编命名"时，命名质量取决于提示，可能出现语义漂移。

替代品

  • 手工维护 SVG 目录：零安装，但语义与去重全靠自觉。
  • Iconify 直接引用：简单，但图标与业务语义脱节。
  • 设计系统自建：最规范，成本最高。
