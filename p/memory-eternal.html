memory-eternal · 本地 + 云端第二大脑

已核实 人工短评 风险 中 🔴 需云端
一句话结论：本机 SQLite 记忆库照旧离线可用，登录云端后"记忆跟着人走"，换机器不用搬家；但云端是别人的服务，私密角色扮演内容要自己掂量。

适合谁

  • 多台机器/多个客户端之间想共享记忆的人。
  • 想要"本地优先、云端可选"而不是纯云记忆的人。
  • 喜欢可审核（待审、回收站、星图）而不是黑盒记忆的人。

解决什么

  • 本机记忆库离线可用；登录云端后同一套知识卡可在每台设备、每个 Agent 读取。
  • 云端按 owner 分目录，每个用户独立 SQLite（cloud-vaults/{owner}/...），物理隔离。
  • 本地库 ↔ 云端库热切换，知识卡/星图/待审/回收站一次性换源，不刷新页面。
  • 整库上传/下载：分片传输 + 断点续传 + 取消 + 重试 3 次，重复内容自动跳过。
  • 离线优先：云端不可达自动熔断回退本地，首屏最多等 3 秒。

风险点

  • 云端登录 = 内容上云：账号来自第三方（MengBot），隐私边界取决于对方服务条款；养鱼的私密剧情尤其要考虑。
  • 同步机制复杂（断点续传、热切换、熔断），出问题时排查成本高。
  • 版本 0.49.x 迭代极快，数据库结构可能变，升级前建议整库备份。
  • 与其它记忆插件混用会造成重复注入。

替代品

  • dsh-fish-memory：纯本地、会淡忘，轻。
  • dsh-mnemon：分层记忆，本地优先，可接第三方 Provider。
  • dsh-prime-memory：自动蒸馏，全自动但不可精确手改。

事实

  • 安装 spec：memory-eternal@0.49.11（npm）· 许可证 MIT · 隔离 profile 安装成功（2026-11-18，22s）
  • 来源：npm · 仓库
  • 审核日期 2026-11-18 · 依据该版本 README 原文
  • 隐私：🔴 需云端（启用云同步后记忆上云；纯本机模式不涉及）

同类插件（同分类已核验）
