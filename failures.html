二、装不上 / 不建议直接装 · 6 条

dsh-purge

npm 包损坏 仅 GitHub 可装 已暂停维护 镜像仓库 破甲/越狱类

npm 上的 dsh-purge 是 0.0.0-stage 占位包，tarball 截断，装不上；且它会写进 profile 的 lockfile，导致之后所有安装都在重试这个坏包。

证据：pnpm 报 Unexpected end of TAR archive at offset 2560；随后 dsh-soul-md / dsh-fish-soul 均因同一 tarball 失败。改用 github:mmparko/dsh-purge 可装成功 1.1.71（72.8s）。

注意：README 自述为网络安全红队/破甲（jailbreak）工具，并写明“暂停更新、暂不收 issue/PR”。当前仓库是上游镜像，上游即将删库。

三、从这些失败里总结的规律

  1. 先看它在不在 npm：返回 404 就只能 github: 装，而 GitHub 源受克隆速度影响，大仓库会超时
  2. 坏包会连坐：一个 tarball 截断的包装进 lockfile 后，同 profile 之后装什么都失败，报错却指向那个坏包
  3. pnpm 11 拦构建脚本：这不是装不上，是"半装"；配置白名单三种写法我们都试过、都无效，只能交互式放行
  4. 静默跳过最难查：有的插件在版本不满足时直接被内核跳过且不报错（如 dsh-bili-scroll 的 README 自述），表现为"装了跟没装一样"
  5. 别用手写脚本改 profile 的 package.json：带 BOM 会让 DSH 解析失败，整个 profile 装不了任何插件
你遇到的失败不在这页？发到讨论区，带上插件名、DSH 版本和完整报错——能复现的我们会复现后写进来。
