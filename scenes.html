场景施工图

这里不给"全部插件"，只给按场景装哪几个、按什么顺序、哪些可以跳过、有什么坑。每一条都对应本站有判断的插件；还没写判断的插件不会出现在这里。

养鱼①长期记忆：聊到第 50 轮还记得设定

角色扮演最大的劝退点是失忆：聊久了模型忘了人物关系、世界观、你定过的规矩。先解决"记得住"，再谈"聊得深"。

装什么、按什么顺序

  1. dsh-prime-memory —— 想要全自动就先试它：对话自动压成 L0→L3 四层，每次调用前召回注入。装完先跑三天，进记忆库抽查写进去的东西对不对。
  2. dsh-mnemon —— 想要"看得见"就选它：工作记忆 / 项目档案 / 长期证据分层，每轮回复下有回合记忆栏，点进去能改。
  3. dsh-fish-memory —— 想要"会淡忘"就选它：带时间戳、按命中注入，久远设定会越记越淡——适合长线剧情而不是精密设定。
  4. meow-memory —— 要"人格与偏好分开存"就选它：七层 SQLite 记忆，soul/user 分层，代价是配置门槛最高。
  5. memory-eternal —— 要"多台机器共享"就选它：本地 SQLite + 可选云同步，热切换不刷新；云同步即内容上云。
  6. dsh-plugin-memory —— 要"记忆能进 git、能搬走"就选它：markdown + SOUL.md，启动时硬注入。
  7. dsh-memory-nebula —— 装了几个记忆插件之后，用它看清楚各自记了什么：只读聚合、顺链检索。

可以跳过

  • 设定不多、只聊几轮 —— 直接在 AGENTS.md 里手写人设与世界观，零安装、完全可控

权限与冲突注意

  • 自动写入的记忆写错会被反复引用，越用越偏：必须定期抽查删改
  • 蒸馏与召回通常要调模型，等于对话内容会经过模型服务
  • 两个都装会重复注入，上下文更早爆

养鱼②上下文瘦身：聊到卡顿怎么救

长对话会把工具输出、日志、命令结果越积越多，最后要么卡、要么贵、要么开始忘事。顺序很重要：先看清楚，再压缩，最后设上限。

装什么、按什么顺序

  1. dsh-context —— 第一步只装它，看上下文里到底装了什么、哪一类占得最多。它只读不改，先诊断再动手。
  2. dsh-live-compact —— 第二步压：本机把长工具输出就地收短，压缩前备份原文、备份失败就放弃；默认到 2 万 token 才动手。
  3. dsh-token-diet —— 第三步兜底：给会话设 Token 预算，到 100% 在下一步请求前停下，避免一晚烧穿。

可以跳过

  • 短会话、或习惯"一到上限就新开会话"的人 —— 新开 + AGENTS.md 比任何压缩都干净

权限与冲突注意

  • 压缩不是无损：被压掉的中间细节虽然有备份，但不会再进上下文
  • 备份会占磁盘，长会话要定期清理
  • 预算到顶是真停任务，长任务可能卡在半路

养鱼③人设防崩：别让角色越聊越像客服

人设崩通常不是模型变笨，而是设定没有稳定载体：被新消息冲淡、被记忆覆盖、被压缩带走。

装什么、按什么顺序

  1. dsh-soul-md —— 要"可控"就选它：把角色写成可切换的人设卡（会话级/工作区级），记忆存成 markdown 你自己能打开改。注意它不保证模型真的去更新人设。
  2. dsh-prime-memory —— 要"自动"就选它：用 L3 画像层自动蒸馏"这个人是谁"，但内容不可精确手改。
  3. dsh-liketavern —— 要"专业养鱼"就选它：兼容 ST 角色卡与世界书，剧情状态按分支隔离、重试不串味；装法特殊（github: 源）且需 Node ≥24。
  4. dsh-fish-soul —— 要"她活在 QQ/B站/抖音"就选它：跨平台单角色人格 + 按人记忆；账号风险与隐私面最大，先想清楚再装。

可以跳过

  • 只做单次短对话 —— 开场把设定贴进上下文就够

权限与冲突注意

  • 两个都装会重复注入人设，上下文更早爆
  • 人设文件被插件覆盖是最常见的崩法，改之前先备份
  • 记忆与人设冲突时通常是记忆赢——需要定期校准

养鱼④隐私排雷：私密聊天别流出去

角色扮演的内容往往是最私密的。装插件前先问一句：它会把我说的东西发到哪里去？

装什么、按什么顺序

  1. dsh-context —— 先用它看清上下文里都有什么，再决定哪些插件值得信任（它本身只读本地）。
  2. cc-safety-net —— 加一道拦截：阻止 Agent 读 .env / SSH 私钥、执行破坏性命令。注意它不是沙箱。

可以跳过

  • 全部用本地模型 + 只装 🟢 插件 —— 风险最低，代价是模型能力

权限与冲突注意

  • 🔴 需云端的插件：内容会离开本机（本站已在每条核验里标出）
  • 桌面自动化类（如 dsh-windows-mcp）会把截图当图片送进对话，屏幕上的一切都在画面里
  • 视频类插件需要 cookies.txt 这类账号凭据，等于把登录态交出去
  • 隐私分级是读 README 后的判断，没有抓包验证，别当审计结论

养鱼⑤离开电脑：手机接着聊、有事提醒你

躺床上想继续剧情、或者长任务跑着要离开座位——这两件事要分开解决：一个管"能接着聊"，一个管"该回来时叫你"。

装什么、按什么顺序

  1. dsh-mobile-plugin —— 要接着聊就装它：手机 App 连回你自己电脑上的 DSH，审批与提问也能在手机上点。
  2. dsh-notify-me —— 只要"叫你回来"就装它：审批/完成时弹通知、响铃；注意只有开了外部转发才会把内容推给第三方。

可以跳过

  • 只是短时间离开 —— 浏览器标签开着就行，不用装

权限与冲突注意

  • 手机插件默认走中转隧道，内容会经过第三方；高隐私用局域网直连
  • 通知转发到 Discord/飞书 等渠道时，标题与摘要会出本机
  • 两边都装要注意重复打扰

养鱼⑥氛围与表达：让对话不像"客服回复"

同一段剧情，纯文字和"有表情、有卡片、有场景感"的体验差很远。这一层不改剧情，只改呈现。

装什么、按什么顺序

  1. dsh-meme —— 加表情：输入框一键发图，AI 按气氛接梗；代价是图片吃上下文。
  2. dsh-pet —— 加陪伴：一百多个透明动画跟随会话状态，可脱离浏览器住成桌面小窗；吃性能。
  3. dsh-dafeiyu —— 要"原生置顶窗"选它：随 DSH 启停、显示任务状态与余额；需要 Python/PySide6 环境。
  4. dsh-genui —— 加结构：把回复变成可点的计算器/表单/图表；与 deep-view 二选一，别都装。
  5. deep-view —— 加结构：需要"选 A 还是 B""填个参数"时，用可点卡片代替一大段文字。
  6. dsh-plugin-wallpaper-engine —— 加场景：把壁纸引擎的 Scene/Web/视频做成对话背景，不花 token，但吃性能。

可以跳过

  • 只想要文字沉浸 —— 装饰层会分散注意力，也用不上

权限与冲突注意

  • 三类都增加上下文或性能开销，长会话要权衡
  • 表情包与壁纸素材的版权要自己确认
  • 装饰装多了排查问题会更难：出 bug 先关装饰层

场景一 · 远程开发：让 Agent 直接在服务器上干活

代码在服务器 / 云主机上，本地只想编辑和发指令。目标是让 Agent 在远端目录里读写、构建、跑测试，而不是本地生成再手动上传。

装什么、按什么顺序

  1. dsh-remote —— 先装它。远程文件树 + 高亮编辑 + 递归搜索 + 终端 + 只读 Git 差异，一个工作区绑一台主机。装完重启 DSH Web，设置里配 SSH 主机再建远程工作区。
  2. @deepseek-harness-tui/dsh-tui —— 只在"想住在终端里"时加装。它把会话搬到命令行，和 dsh-remote 不冲突，但两套界面偏好各自独立。

可以跳过

  • 已经有 VS Code Remote 且习惯在编辑器里跑命令 —— 装了反而多一套目录树

权限与冲突注意

  • SSH 密码 / 私钥由插件保存并自动应答，这是最大风险面；多用户机器上不要用
  • Agent 拿到的是远端 shell 能力，先用非生产目录试
  • SSH 通断会同时影响编辑、搜索、终端

场景二 · 成本监控：先知道钱花在哪

同时用 API 和多份 Coding Plan / 订阅，想按会话、按模型、按日期看清消耗，并在超支前收到提醒。

装什么、按什么顺序

  1. dsh-cost-meter —— 主力选择。会话级费用、模型排行、缓存命中率、套餐额度聚合、预算提醒都在里面；先只配你真正在用的那几家账号。
  2. dsh-whale-widget —— 只想看余额时的轻量替代：右下角挂一个小鲸鱼，不占主界面。不适合要做月度归因的人。

可以跳过

  • 只用单一订阅、且平台自带账单页面 —— 多装一个会重复采集

权限与冲突注意

  • 查订阅额度通常要各家 Cookie / API key / AK-SK，别为了"看得全"把所有账号都填进去
  • API 费用与 Plan 等值费用分开统计，数字准不准取决于你的配置，别直接拿去报销
  • 历史记录会占本地存储，确认保留范围

场景三 · 记忆管理：让下一次会话不用重新自我介绍

长期在同一个项目上和 Agent 协作，受够了每次会话都从零开始；但也不想把所有内容塞进一个记忆库。

装什么、按什么顺序

  1. dsh-mnemon —— 结构最讲究的一个：工作记忆 / 项目档案 / 长期证据分层，按问题需要检索；默认本地存储，也能接第三方 Provider。第一周先用默认配置。
  2. meow-memory / dsh-fish-memory —— 工程化偏好选 meow-memory（七层 SQLite + 反思折叠）；只想记事实、要轻量选 dsh-fish-memory。

可以跳过

  • 项目里已经有 AGENTS.md 且规则不多 —— 先写好约定文件，不够再上记忆插件

权限与冲突注意

  • 自动写入的记忆一旦写错会被反复引用，定期抽查删除
  • 接入第三方 Provider 意味着项目内容离开本机
  • 配置项很多，第一天上手容易配出自己也看不懂的组合

场景四 · 联网搜索：没有官方 key 也要能搜

内置 web_search 依赖 DeepSeek 官方 key；用第三方模型供应商时要么搜不了，要么照样扣官方账户的钱。

装什么、按什么顺序

  1. dsh-free-search —— 注册多引擎搜索 provider 并自动回退；先只开默认的免费引擎，别开抓页面那 5 个。

可以跳过

  • 已经配好官方 key、且不介意按官方计费 —— 内置能力足够，不必多装一层

权限与冲突注意

  • 抓页面引擎（百度/360/搜狗/微信/头条）会把整段出口 IP 打标，默认关闭就别打开
  • 免 key 用各家接口，商用前自行确认对方条款
  • 免费引擎会限流改版，结果质量会波动

场景五 · 桌面自动化：操作没有 API 的软件

内部系统、老客户端、只有界面没有接口的活，只能靠截屏 + 点按 + 输入。

装什么、按什么顺序

  1. dsh-windows-mcp —— 通过 DSH 自带 MCP 桥接入 Windows-MCP；默认关闭，按会话点亮胶囊才生效。

可以跳过

  • 任务只在浏览器里 —— 用浏览器类工具，权限面小得多

权限与冲突注意

  • 注册表读写、进程启停、键鼠输入在同一套授权下，重活先拿测试机试
  • Screenshot 会把屏幕上的一切作为图片送进对话
  • 依赖 uvx 与上游 Windows-MCP 版本，上游变了工具清单会变

场景六 · 多方案对比：一次拿到几个版本再挑

同一个需求，想要 2–4 种实现并排看，而不是反复"再来一版"。

装什么、按什么顺序

  1. dsh-agent-compare —— 并行跑 2–4 个版本，回答 / 文件 / 可运行网页并排比较，选定后写理由再继续主对话。

可以跳过

  • 需求本身很明确、只需要一次输出 —— 并行 2–4 路等于 2–4 倍成本

权限与冲突注意

  • token 消耗成倍增加，配合费用统计插件用
  • 多版内容都会进会话，长会话容易吃满上下文

场景七 · 会话整理：列表越来越长之后

会话上百条以后，侧栏翻不到想要的那一轮；暂时不做的项目舍不得删，又不想天天看到。

装什么、按什么顺序

  1. @michengai/dsh-archive-manager —— 归档 / 恢复 / 收藏 + 正文全文检索，还能按闲置天数批量归档并撤回。

可以跳过

  • 会话不到 50 条、且不介意侧栏长 —— 内置列表够用

权限与冲突注意

  • "永久删除"是真的永久，先拿不重要的会话试一次
  • 批量归档会动很多会话，操作前看预览列表
  • 会读取消息正文建索引

场景八 · 让模型"看"视频：分镜与可引用帧

纯文本模型看不了视频；逐帧喂图又贵得离谱。要的是能引用某一格、还能再放大看几秒。

装什么、按什么顺序

  1. dsh-video-storyboard —— 把视频压成一张带时间戳与台词的宫格图，模型可引用"第 5 格"，再按需放大。

可以跳过

  • 只要两三帧 —— 手动截帧 + 图片工具更省事

权限与冲突注意

  • 要自备 ffmpeg、yt-dlp 与 cookies.txt（等于账号凭据）
  • 宫格图会把画面内容送进对话
  • 抓站点涉及平台条款，自用与再分发边界自己判断

场景九 · 视觉定制：把界面换成愿意天天看的

长时间盯界面，配色与留白直接影响状态；团队展示还需要一点统一气质。

装什么、按什么顺序

  1. dsh-dream-skin —— 8 套预设皮肤 + 壁纸 + 强调色，纯 token 实现，不注入、不改安装包，一键还原。

可以跳过

  • 内置深浅色够用 —— 换肤只是审美，不是功能

权限与冲突注意

  • README 提到维护坐标从 GitHub 迁到 gitcode、暂停"已验证"背书，源码托管状态需自行确认
  • 壁纸支持外部 URL，用不可信地址有隐私风险
  • 迭代很快，版本号已到 11.x
