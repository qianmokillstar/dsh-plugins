收录规则与标准

本站为第三方非官方站点，与 DeepSeek / DeepSeek Harness 官方无关联、无授权、无背书。

收录门槛（三选一才算"已核实"）

  • npm 包的 package.json 声明了 dsh.bundle.patch
  • 仓库根 package.json 声明了 dsh 字段（bundle / client / profile）
  • 仓库自带 cordis.patch.yml

只有 README 提到安装方式、拿不到包声明的，可以收录，但必须标「未核实」，不得标「已核实可安装」。

判断标准

每条人工判断必须回答四问，缺一不发布：

  • 适合谁：人群与具体场景，不写"所有人"
  • 解决什么：写能力，能量化就量化
  • 风险点：至少一条真会出事的（凭据 / 隐私 / 成本 / 权限 / 外部依赖）
  • 替代品：至少两个，包含"什么都不装"

排序与收费

推荐序由人工判断给出，不接受付费、不接受指定排名。当前站点没有任何赞助、推广位或付费收录。若未来出现商业合作，会在对应位置显著标注「赞助/推广」。

引用与转载

欢迎媒体、公众号、作者引用本站结论，但请守三条：

  • 带上日期与版本：核验结论只对"某日某版本"成立，转述时请保留，否则会误导读者
  • 不要断章取义：只截"优点"、删掉风险点，等于篡改结论；请至少保留风险点或链回原文
  • 注明来源：写明"来自 DSH 插件站（非官方第三方）"并附页面链接

整站转载请联系（讨论区）；本站内容为独立评测，插件版权归各作者。

为什么我们不按 star 排序

因为在 DSH 生态里，star 与"能不能装"几乎不相关：

  • 实测抓取 topic:dsh-plugin 的前 400 个仓库，164 个根本不是插件（图床、视频下载、逆向工具挂了同一个 topic 蹭曝光）
  • star 最高的若干仓库里，有的是"给 Agent 用的技能包"，有的是"套壳客户端"，并不是可安装的 DSH 插件
  • 下载量可以被搬运与镜像放大，也不能单独代表质量

所以本站的做法是：先验证它是不是插件、能不能装，再看判断；star 与下载量只作为参考列在卡片上，不参与主排序。

不收录

  • 要求关闭沙箱 / 审批 / 权限模型才能用的
  • 收集用户数据但不说明用途与存储位置的
  • 只有壳、功能与描述不符的
  • 冒用官方名义但无官方关系的（社区项目会单独标注）
