# 你的 AI 为什么会失忆？我实测了 8 个记忆插件

（面向没听过本站的人写的。可作为公众号/知乎/掘金首篇。）

---

聊到第 50 轮，它突然问你"我们刚才在说什么"——这不是模型变笨了。

**上下文是有上限的。** 到了上限，要么压缩（丢细节），要么新开一轮（全丢）。记忆插件的存在，就是为了把这个上限往后推。

问题是：市面上的记忆插件有十几种，机制完全不同。我花了三天，把 8 个主流插件真装进 DSH（DeepSeek Harness），记录下它们的真实行为。

## 三种完全不同的机制

**① 硬注入型**：每轮都往提示词里塞一段记忆。
代表：`dsh-mnemon`、`dsh-plugin-memory`
- 优点：模型不用主动查，稳定
- 代价：**每轮都在交"固定税"**。有作者实测 mnemon 会给系统提示加约 4.8KB

**② 检索型**：提示词只放索引，细节等模型来查。
代表：`dsh-loci`、`dsh-fish-memory`
- 优点：空库时注入 0 字节；只读回合提示词逐字节不变，前缀缓存友好
- 代价：**模型偷懒就不会查**；索引写得不好等于没有

**③ 蒸馏型**：后台把对话压成分层记忆，调用前自动召回。
代表：`dsh-prime-memory`（L0→L3 四层）
- 优点：全自动，不用你管
- 代价：**自动写入意味着写错也会被反复引用**；而且蒸馏要调模型，内容会经过服务方

## 几个只有真装过才知道的坑

- `dsh-plugin-memory` 的早期版本（0.19.x）调用了改名后的 API，**表现是"开启插件后无法新建会话"**。0.19.2 修了，但你得知道要升级。
- `meow-memory` 的七层记忆很强，但 README 默认是葡萄牙语，中文用户第一眼会懵。
- `memory-eternal` 支持云同步——**意味着你的记忆会上传到第三方**，私密剧情要考虑清楚。
- `dsh-memory-nebula` 会把别的插件的记忆只读聚合成一张星云图，跨项目联想很方便，**但也会把 A 项目的设定带进 B 项目**。

## 我的建议（按场景）

| 你的情况 | 选什么 |
|---|---|
| 设定多、想自己掌控 | `dsh-mnemon`（看得见每轮记忆，可手改） |
| 上下文贵、在意缓存 | `dsh-loci`（只放索引） |
| 不想管、要全自动 | `dsh-prime-memory`（但记得定期抽查） |
| 长线剧情、允许淡忘 | `dsh-fish-memory` |
| 只聊几轮 | **什么都别装**，写个 `AGENTS.md` 就够 |

## 一条铁律

**别同时装三个以上记忆插件。** 它们会重复注入，上下文反而更早爆。
