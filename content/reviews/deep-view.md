# deep-view · 在对话里画交互视图

> 一句话结论：让模型把"用 Markdown 说不清"的内容画成可点的卡片——图表、滑块、表单；纯展示秒回，带输入的要等你回答。

## 适合谁

- 经常需要模型输出对比表、参数可调的计算器、一页小表单的人。
- 做角色扮演/陪伴时，想让模型给你"带选项的剧情分支"而不是一大段文字的人。
- 自己写 Agent，想复用一套视图渲染核心的人（README 提到 `src/core`、`src/react` 供宿主复用）。

## 解决什么

- `show_view` 工具：图表（bar/hbar/line/area/donut）、指标、表格、进度、callout、来源、沙箱 HTML。
- 输入控件：滑块、数字、单选、开关，**页面内即时重算，不触发模型调用**。
- 回答控件：选项、确认、表单，回答作为一条普通用户消息送达，Agent 下一轮能读到。
- 只有根 Agent 能开需要等待的视图，子 Agent 会被拒绝——避免子任务卡住等人。

## 风险点

- **安装方式不是常规 add**：README 给的是往 `cordis.patch.yml` 插一条 `insert`，与"装 npm 包"不是一回事，容易装完看不到效果。
- `html` 视图是沙箱标记（无网络、无应用访问、不能回传答案），但仍是渲染任意 HTML，**只应对可信输出使用**。
- 带回答控件的卡片会一直开着，直到你回答或发出别的消息；忙碌时容易堆积。
- 版本 0.1.x，接口仍在早期。

## 替代品

- **`dsh-genui`**：同属"生成式 UI"方向，组件更偏表单/仪表盘。
- **Markdown 表格 + 手动追问**：零安装，够用就别加。
- **`dsh-agent-compare`**：比较的是多版实现，不是视图渲染。
