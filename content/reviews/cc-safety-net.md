# cc-safety-net · 危险命令与密钥访问拦截

> 一句话结论：在工具调用执行**之前**拦住删库、改权限、读 `.env`/SSH 私钥这类操作；它明说自己不是沙箱，别把它当安全边界。

## 适合谁

- 让 Agent 长时间自己跑、担心它一条 `rm -rf` 或 `chmod` 把环境搞坏的人。
- 机器上有 `.env`、SSH 私钥、云厂商凭据，怕被误读或被外传的人。
- 想给团队加一道"最低限度的护栏"，但不想上完整沙箱的人。

## 解决什么

- 在工具调用执行前解析命令**做了什么**，命中破坏性操作或敏感文件访问就拦下。
- 包装命令、调换参数顺序**绕不过去**（README 明确说明）。
- 配置文件坏了会回退到安全默认值，而不是让 Agent 停摆。

## 风险点

- **它不是沙箱**：不隔离进程、不设文件权限、不监控网络出口。被绕过的路径（解释器、脚本内联、动态拼接）它不保证覆盖。
- 拦截规则是模式匹配，**未知命令可能漏报**；把它当成"多一层提醒"而不是"安全保证"。
- 误杀会挡住正常操作，需要自己维护白名单。
- README 里有赞助商区块，与功能无关，介意可忽略。

## 替代品

- **官方沙箱 / 权限预设**：真正隔离进程与文件的是 DSH 的沙箱能力，这是底线，不能省。
- **`dsh-ops`**：偏 Windows/Linux 原生工具与 PowerShell 集成，不是拦截器。
- **人工审批（approval）**：最稳但最慢。
