# dsh-live-compact · 边做边压

> 一句话结论：目前看到最认真的"上下文瘦身"实现——本机压缩、切点前的原文不动、压缩前先备份、备份失败就放弃；还带了可复核的对照测评。

## 适合谁

- 一段对话做久了，日志、命令输出、工具结果越积越多，上下文快爆的人。
- 关心"压缩后会不会失忆"，想知道有没有对照数据的人。
- 用云端 API、在意费用与缓存命中率的人。

## 解决什么

- 每轮结束时检查，把**能安全收短的长输出**就地整理，**在本机完成，不再请求模型**。
- 只替换选中的那一段，**切点前面的内容保持原样**；压缩前备份原文，备份失败就保留原内容。
- 默认上下文到 2 万 token 才开始检查；接近窗口上限时，DSH 仍可调用模型做一次大摘要。
- README 给出对照测评：同一真实会话 15 道回忆题两边都 15/15；日志中段细节两次都是 3/3（原版一次 1/3）。
- `SPINE_THUNDER` 实验性模型摘要模式，默认关闭，本机模型建议保持关闭。

## 风险点

- **"压缩"不等于"无损"**：它只动工具输出那类长内容，但一旦你依赖被压掉的中间细节，仍然查不到原文（虽然有备份）。
- 备份会占磁盘，长会话下需要关注备份目录体积与清理策略。
- 默认阈值 2 万 token 对短会话没意义；对小窗口模型可能偏晚。
- 版本 1.1.x，README 的测评数据对应特定版本，升级后结论可能变。

## 替代品

- **官方压缩（`dsh-compaction-basic` 等）**：由上下文接近上限时触发大摘要，简单但会丢细节。
- **`dsh-context`**：只观察不压缩，适合先确认到底是谁吃了上下文。
- **手动新开会话 + AGENTS.md**：零安装，最彻底，但丢历史。
