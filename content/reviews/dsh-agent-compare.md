# dsh-agent-compare · 鲸挑细选 · 同需求多方案对比

> 一句话结论：想让 AI 给同一需求出几个不同方案、再自己挑一个落地的人，这是目前最顺手的"赛马"工具；代价是同一件事的 token 花 2–4 倍。

## 适合谁

- 做 UI / 落地页 / 小工具时，想一次拿到多种风格候选，而不是反复"再来一版"的人。
- 团队评审：需要把 2–4 个实现并排摆出来，看过程、看文件、看可运行页面再决定的人。
- 对"盲选"有兴趣，想避免自己先入为主偏爱某种风格的人。

## 解决什么

- 在主对话里把同一需求并行分给 2–4 个版本，比较**回答**、**文件**或**可直接操作的网页**。
- 每版有独立的蓝色标签（A–D），盲选模式下选完才揭晓风格和模型，减少偏见。
- 每个"过程"按钮展开该版的思考、工具调用和改动，最新三步实时滚动。
- 选定后可以写明理由、保存结果，再接着在主对话里继续，不用重开一轮。

## 风险点

- **成本翻倍**：2–4 路并行意味着 2–4 份模型调用与工具执行；README 没有给出费用上限提示，建议自己在预算上留余量（可配合费用统计类插件）。
- **上下文膨胀**：多版回答、文件和网页都会进会话，长会话里容易把上下文吃满，需要主动压缩或分会话。
- **版本节奏快**：3.x 迭代频繁（3.1.0 合并了 2.1.0 与 3.0.0 的改进），跨版本行为有变化，升级前建议看更新说明。
- 对比页面的"可运行"是本地渲染的真实页面，仍需自己确认没有执行来路不明的脚本。

## 替代品

- **官方能力**：`subagent` 委派 + `workflow` 编排可以自己搭多路并行，但没有内置的并排比较界面。
- **`deep-view` / `dsh-genui`**：把结果渲染成图表、表单等交互视图，适合展示而非"选方案"。
- **手工做法**：同一提示词开多个会话，复制结果对比——零安装成本，但没有 A–D 标签和过程对照。
