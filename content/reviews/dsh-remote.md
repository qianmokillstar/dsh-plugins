# dsh-remote · SSH 远程工作区

> 一句话结论：把"在服务器上改代码"变成 DSH 的一等公民——远程文件、搜索、终端、Git 差异和 Agent 都在同一个工作区里；前提是你愿意把 SSH 凭据交给它管理。

## 适合谁

- 代码跑在远程服务器 / 跳板机 / 云主机，本地只负责编辑和发指令的人。
- 需要多台主机、多个项目并行，又不想来回 `ssh` 切窗口的人。
- 想让 Agent 直接在远端跑构建、测试、看日志，而不是"本地生成 → 手动上传"的人。

## 解决什么

- 每个工作区绑定一台主机和一个目录，多个远程工作区可独立并行。
- 远程文件树 + 语法高亮编辑 + 递归搜索文件与内容，不用先同步镜像。
- 远程终端进入当前会话目录，支持多终端并行；已保存的凭据可自动应答。
- 只读的 Git 差异视图（工作区 / 已暂存分栏），能点改动行定位源码，不提交、不动暂存区。
- Agent 在所属远程工作区里读写、构建、测试，工具卡展示真实退出码与构建输出。
- 本地项目也能用同一套 IDE 三栏布局，无需配置 SSH。

## 风险点

- **凭据集中**：SSH 密码 / 私钥由插件保存并在需要时自动应答。这是便利的来源，也是最大风险面——请确认保存位置与备份策略，不要在多用户机器上使用。
- **远程命令执行**：Agent 获得的是远端 shell 能力，误删、误改的风险落在服务器上而不是本机；建议先用只读账号或非生产目录试。
- **网络依赖**：SSH 连通性差时，搜索、编辑、终端都会一起变慢或失败。
- 编辑器保存时会检测远端冲突并保留 CRLF，但多人同时改同一文件仍可能冲突，建议配合版本控制。
- 安装后需要重启 DSH Web 并刷新页面；升级同理，否则跑的可能是旧版本。

## 替代品

- **DSH 内置 SSH 能力**（`dsh-ssh` 相关 bundle）：适合脚本化、少量文件读写，没有工作区与 IDE 布局。
- **`dsh-ops`**：偏 Windows/Linux 本机与 PowerShell 集成，不是远程工作区。
- **传统做法**：VS Code Remote + DSH 本地会话，编辑器体验成熟，但 Agent 与远程目录是割裂的。
