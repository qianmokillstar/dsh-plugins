# @deepseek-harness-tui/dsh-tui · 终端界面

> 一句话结论：给习惯住在终端里的人一个"不离开命令行也能用 DSH"的入口；它只吃公开导出、卸载不留补丁，但仍在公开测试期。

## 适合谁

- 长期在 tmux / SSH 终端里工作，不愿意为了一次对话切浏览器的人。
- 想要纯键盘操作、`/` 与 `@` 补全、历史搜索的人。
- 喜欢像素鲸鱼、TPS 仪表盘这类"有性格"的终端 UI 的人。

## 解决什么

- 终端内交互式 UI：流式 Markdown、工具卡片、`/` 与 `@` 补全、`#L12-14` 行范围引用、历史搜索，中英双语界面。
- 首页启动器 + 四步首次引导向导（账号与模型 / 语言与主题 / 模型与工作区 / 快捷键），可用 `/setup` 重跑。
- 双 Esc 时间回溯、上下文进度条、TPS 仪表、实时工作状态、流式思考展示。
- 只消费 DSH 的公开导出，不改核心；正在从"挂载插件"过渡到"自带入口的应用"，卸载不留补丁。
- 图片 `@path` 引用与粘贴图片共用同一套准入与缩放策略。

## 风险点

- **公开测试期**：README 自己标注 public beta，0.20.x 的接口与交互仍在变；遇到问题先看版本更新说明。
- **定位在变**：从挂载插件转向独立应用的 composition root，迁移期可能同时存在两种启动方式，文档容易对不上。
- **模型/供应商耦合**：启动向导会引导登录订阅或添加 API key，步骤多，选错了要在 `/provider` 里改回来。
- 终端能力受终端本身限制：图片、色彩、按键在不同终端（Windows Terminal / tmux / SSH）表现不一致。
- 与 Web 界面并行使用时，偏好设置各自独立，容易"为什么这里是这样"。

## 替代品

- **官方 `dsh` CLI + `dsh-headless` bundle**：一次性任务或脚本化调用的官方路径，没有交互式 UI。
- **`dsh-ops`**：偏 Windows/Linux 原生工具与 PowerShell 集成，不是 TUI。
- **浏览器 Web GUI**：功能最全，只是要在终端外切窗口。
