# dsh-ops · 省 token 的工具集替换

> 一句话结论：它不是让你多几个功能，而是**用更省 token 的工具面替换掉官方那套**——返回更紧凑、带行号、错误更清楚；代价是你得接受"工具被换掉"。

## 适合谁

- 长任务多、上下文总被工具输出撑爆的人（养鱼长对话同样受益）。
- Windows 上想用 `ops_bash` 替代 pwsh、又不想完全放弃官方 Shell 的人。
- 愿意折腾 PTC / Native 预设，追求"每轮少花几千 token"的人。

## 解决什么

- 提供 ops 系列工具，并**隐藏部分官方工具**，换来更紧凑的返回格式（带行号、错误回馈更好），减少报错循环与调用轮次。
- Bash 与宿主 Shell 可独立配置；Windows 下 `ops_bash` 可替代 pwsh，也可保留官方 Shell。
- 第五个内置模式 `ops-ptc`：按根 `run_code` 程序形状给 `additionalContexts` 纠偏，不阻断、不改写程序。
- 启用 DSH 预留的 `tools_addition` 动态工具加载：PDF、Word 读取、超多文件批量修改这类高级功能按需加载，**不撑系统提示词**。
- PTC SDK 目录含 18 个 API（15 个文件/文档工具 + 批处理、结果引用、加载器）。

## 风险点

- **换掉工具面是有代价的**：习惯官方工具输出格式的人会不适应；某些第三方插件若依赖被隐藏的官方工具，可能失效。
- 它自称"低侵入、广泛兼容"，但工具面替换属于**行为层改动**，出问题时排查链更长。
- 多套预设（Native / PTC / ops-ptc）容易配混，默认模式有按钮可设，但改错会影响新会话。
- 版本 0.5.x，迭代快。

## 替代品

- **官方工具面不换**：稳，但长任务 token 消耗高。
- **`dsh-live-compact`**：不替换工具，直接压输出，思路不同但目标一致。
- **`dsh-token-diet`**：只管预算，不改工具。
