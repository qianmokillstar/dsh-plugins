# dsh-soul-md · 人设卡 + 文件记忆

> 一句话结论：把"人设"做成可切换的卡片（会话级/工作区级/默认），记忆存成 markdown 文件由模型自己读写——**养鱼圈最对症的人设方案**，但它不保证模型一定去改人设。

## 适合谁

- 同时养多个角色/多个项目，需要"这个会话用这个人设"的人。
- 想要"人设和记忆都能自己打开看、自己改"的人（markdown 文件，不用信插件黑盒）。
- 在意子代理污染：默认不向子代理注入人设与记忆。

## 解决什么

- **人设卡**：插件页创建/编辑/设默认；新会话页或聊天标题栏可给单个会话换卡，也能隐藏选择器。
- **解析顺序**：会话选择 → 工作区人设 → 默认卡 → 不启用，规则清晰。
- **文件记忆**：`memory_read` / `memory_append` / `memory_rewrite` 读写记忆；`soul_read` / `soul_update` 读写人设卡。
- **分层记忆**：常驻 `core.md` + 按主题读取的 `topics/*.md`，支持 `memory_search`、关键词召回、压缩后补偿，可分别关闭。
- 每张卡可单独关记忆，不影响人设本身；子代理默认不注入。

## 风险点

- **"不保证自动发生"**：README 明说人设变化与记忆写入取决于模型是否真的调用工具——也就是说模型偷懒时，人设不会自己更新。
- 切换工作区可能打开另一个空白会话，**人设选择要重新确认**，容易"以为在用人设其实没有"。
- 人设卡是 markdown 文件，改错会直接影响对话风格；多卡片管理容易混淆。
- 与记忆类插件（prime-memory / mnemon / meow）叠加会重复注入，上下文更早爆。

## 替代品

- **AGENTS.md 手写人设**：零安装、最稳，适合单角色单项目。
- **`dsh-prime-memory` L3 画像**：自动蒸馏"这个人是谁"，但不可精确手改。
- **`dsh-fish-soul`**：另一个 soul 方向实现（本轮未取到 README，未核实）。
