# 路线图：做一个"能快速判断该装哪个"的插件站

定位收窄后的版本。目标不是收录最多，而是**搜一个插件，立刻知道它能不能用、适合谁、有什么坑**。

## 已完成（前三周的大部分）

| 项 | 状态 | 位置 |

**实测结论**：`topic:dsh-plugin` 有 32,055 个仓库，但大量无关项目（图床、视频下载、逆向工具）挂了这个 topic。抓 400 个后按"package.json 有 dsh 声明 / 有 cordis.patch.yml / README 有真实安装特征"过滤，**236 个是插件，164 个是噪声**。所以"直接抓 topic 就能用"不成立，过滤是必需环节。

## 接下来要做的（按优先级）

1. **把"未核实"变成"实测"**：试装、记录 DSH 版本与日期。现在所有兼容状态都是声明值，这是最大的可信度缺口。
2. **补到 30 个判断**：优先补用户真会装的（远程、记忆、费用、搜索、终端）。
3. **上线**：静态站直接传，见 `docs/PUBLISH.md`。
4. **发社群收集第一轮反馈**：重点不是流量，是"哪条判断不准"。

## 明确不做

- 用户账号、评论、评分
- 付费产品、赞助位、卖排名
- 推荐算法（数据量不够时，人工推荐序比算法准）
- 社区投稿的实时审核（先人工处理，不建后台）

## 三条硬规则（写死在这里）

1. **不收录没验证过的插件**：要么试装过，要么在页面明确标注"未核实"。现在 290 条标"已核实"（有包声明或 bundle 补丁）、20 条标"未核实"（仅 README 线索）。
2. **判断必须具体**：不写"功能强大"，写"适合 X、不适合 Y、已知问题是 Z"。
3. **数据可追溯**：每条都有版本、日期、来源链接；兼容状态必须写测试的 DSH 版本。
