装不上？先在这里查

下面每一条都是本站真装出问题后记录下来的：症状 → 原因 → 修法 → 证据。输入你看到的关键词即可过滤。

装 A 插件，报错却指向 B（例如 dsh-purge-0.0.0-stage.tgz），之后装什么都失败

原因：某个损坏的占位包被写进该 profile 的 lockfile，之后每次 add 都会重试它；真正要装的那个其实没轮到。

怎么修：

  1. 先看报错里的 tarball 文件名，确认是哪个包坏了
  2. 在该 profile 里移除它：dsh plugin --profile <prof> remove <坏包名>
  3. 仍不行就删掉该 profile 的 node_modules 与 pnpm-lock.yaml 后重装
  4. 最省事：换一个干净 profile 重来

证据：本站实测：npm 上 dsh-purge@0.0.0-stage 是截断的 tarball，装了它之后 dsh-soul-md、dsh-fish-soul 全部因同一个坏包失败。

看到 + 插件名 版本号，但最后 ERR_PNPM_IGNORED_BUILDS，插件不生效

原因：pnpm 11 默认不允许依赖执行构建脚本（安全策略）。包已经落地并写进 dependencies，但没进 dsh.profile.bundles，所以不会启动。本站记为「半装」。

怎么修：

  1. 在 profile 目录执行 pnpm approve-builds，逐个确认哪个依赖要跑脚本、判断可信后放行
  2. 然后重新 add 一次，让它进入 bundles
  3. 注意：package.json 的 pnpm 字段、pnpm-workspace.yaml 的 onlyBuiltDependencies、--config 传参，这三种配置写法我们实测都绕不过去

证据：本站实测：@michengai/dsh-im-connect、@tencent-connect/dsh-qqbot、dsh-session-superagent 三个都卡在这里。

安装报 "not in the npm registry"，或者 404

原因：这个包根本不在 npm 上，只发布在 GitHub 仓库。

怎么修：

  1. 改用 GitHub 源：dsh plugin --profile <prof> add github:owner/repo
  2. 仓库地址去插件 README 的「安装」一节找，不要猜
  3. 克隆慢的时候会超时，见下一条

证据：本站实测：dsh-purge-community、dsh-purge-safe、dsh-liketavern、gal-view 都不在 npm。

用 github: 源安装，卡很久没有输出，最后超时

原因：DSH 会先克隆仓库，速度受网络与仓库体积影响。大仓库或网络差时会超时。

怎么修：

  1. 换个时间重试，或先确认网络能正常访问 github.com
  2. 先确认作者有没有发布预编译包或 npm 版本
  3. 重新执行一次（已下载的部分通常会被复用）

证据：本站实测：dsh-liketavern 156 秒成功；dsh-tavern 超过 30 分钟超时；gal-view 两次都超过 15 分钟。

安装器报 incompatible with dsh，拒绝安装

原因：插件的 engines.dsh 与当前 DSH 版本不匹配，安装器主动拦截。

怎么修：

  1. 优先升级/降级插件版本，找一条匹配你 DSH 的版本线
  2. 不要轻易用 allow-version 强装——那等于自己承担崩溃与数据丢失
  3. 确认你装的是正确版本线的 dist-tag（有的插件按 DSH 主线分开发布）

证据：本站实测：billion-context-dsh@0.2.27 对 DSH 0.2.2-rc.3 被拒。

装完了，但界面里没有任何变化，也没有报错

原因：常见三种：① 版本不满足，内核静默跳过该插件；② 包没进 profile bundles；③ 它依赖 webServer 之类的服务，在精简 profile 里 pending。

怎么修：

  1. 跑 dsh --profile <prof> --dump-config，看这个插件有没有出现在组合里
  2. 在组合里但启动后 pending → 缺宿主服务（换到带 Web 的 profile）
  3. 不在组合里 → 重新 add，或检查是否处于「半装」
  4. 个别插件（如 dsh-bili-scroll）README 明确说版本不满足会被静默跳过，先核对版本

证据：本站启动核验实测：archive-manager 与 dream-skin 在最小 profile 里 pending，等待 webServer。

突然什么插件都装不了，报 SyntaxError: Unexpected token

原因：手改过 profile 的 package.json，保存时带了 UTF-8 BOM，DSH 的 JSON 解析不接受 BOM。

怎么修：

  1. 用编辑器把该文件另存为「UTF-8 无 BOM」
  2. 或用命令行去掉 BOM（node 一行即可）
  3. 改之前先备份该文件

证据：本站实测：PowerShell 的 Set-Content -Encoding UTF8 会写 BOM，导致整个 profile 无法安装任何插件。

同一个插件装了两遍，行为异常或看到两个入口

原因：同一个包分别用 npm 名与 github: 源装过，两者并存冲突。

怎么修：

  1. 先 remove 其中一种装法，再重新装你需要的那个
  2. 统一只用一种来源（推荐 npm 已发布版）

证据：本站实测：dsh-whale-widget 的 README 明确警告两种装法不要混用。
