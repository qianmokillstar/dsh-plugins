dsh-cost-meter · 会话费用与额度统计

已核实 人工短评 风险 中
一句话结论：DSH 里最像"财务仪表盘"的插件——按会话、模型、日期算钱，还能把各家订阅额度拉到一个界面里；代价是要给它联网和一部分账号凭据。

适合谁

  • 同时用 API 和多份 Coding Plan / 订阅，想知道"这个月钱花在哪"的人。
  • 团队里要给 Agent 使用定预算、设上限的人。
  • 喜欢看趋势、模型排行、缓存命中率和 Token 热图的人。

解决什么

  • 输入区、标题栏、每轮回复显示费用；展开可看单价、Token、输入内容和工具结果，父子代理费用分开归属。
  • 按日期 / 渠道 / 模型筛选，看趋势、模型排行、缓存命中率与 Token 热图；单个或全部会话可导出。
  • 内置 170+ 模型价格目录，可编辑单价、倍率与峰谷档位，同步 DeepSeek 官方价与 OpenRouter 目录。
  • 套餐额度聚合：Codex/ChatGPT、OpenCode Go、MiniMax、Claude、GLM、Kimi、千问、MiMo、OpenDesign 等，另有 CLIProxyAPI 多账号与自定义 HTTP 余额查询。
  • 预算提醒：按日 / 月 / 累计 / 自定义日期设预算，峰谷倒计时与切换前弹窗、系统通知。
  • 侧栏、输入区、额度横条的显示可自定义，支持中英双语、深色主题和手机端。

风险点

  • 凭据覆盖广：要查订阅额度，往往需要各家账号的 Cookie、API key 或 AK/SK。这是敏感信息，建议只配你真正在用的那几家，别为了"看得全"把所有账号都填进去。
  • 联网行为多：官方价格同步、OpenRouter 目录、各家额度查询都会出网；用代理或离线环境时部分功能会失败。
  • 统计口径要自己对：API 费用与 Plan 等值费用是分开统计的，峰谷倍率也能手改——数字准不准取决于你的配置，别直接拿去报销。
  • 历史记录会占本地存储，README 提到可设保留范围与管理存储，但默认策略需自己确认。

替代品

  • dsh-whale-widget：右下角余额小鲸鱼，看余额/今日消耗/峰谷，轻量得多，但没有会话级明细与导出。
  • 官方 dsh-token-meter + dsh-experimental-client-ui-stats：内置的 Token 计量与每轮成本表，够用但只有基础维度。
  • dsh-connect-workbuddy：专注把 WorkBuddy 余额与积分接进来，不是通用计费面板。
