场景施工图

这里不给"全部插件"，只给按场景装哪几个、按什么顺序、哪些可以跳过、有什么坑。每一条都对应本站有判断的插件；还没写判断的插件不会出现在这里。

当前覆盖 3 个场景，全部基于已审核插件的 README 与核验记录。顺序建议是判断，不是硬性依赖。

场景一 · 远程开发：让 Agent 直接在服务器上干活

代码在服务器 / 云主机上，本地只想编辑和发指令。目标是让 Agent 在远端目录里读写、构建、跑测试，而不是本地生成再手动上传。

装什么、按什么顺序

  1. dsh-remote —— 先装它。远程文件树 + 高亮编辑 + 递归搜索 + 终端 + 只读 Git 差异，一个工作区绑一台主机。装完重启 DSH Web，设置里配 SSH 主机再建远程工作区。
  2. @deepseek-harness-tui/dsh-tui —— 只在"想住在终端里"时加装。它把会话搬到命令行，和 dsh-remote 不冲突，但两套界面偏好各自独立。

可以跳过

  • 已经有 VS Code Remote 且习惯在编辑器里跑命令 —— 装了反而多一套目录树

权限与冲突注意

  • SSH 密码 / 私钥由插件保存并自动应答，这是最大风险面；多用户机器上不要用
  • Agent 拿到的是远端 shell 能力，先用非生产目录试
  • SSH 通断会同时影响编辑、搜索、终端

场景二 · 成本监控：先知道钱花在哪

同时用 API 和多份 Coding Plan / 订阅，想按会话、按模型、按日期看清消耗，并在超支前收到提醒。

装什么、按什么顺序

  1. dsh-cost-meter —— 主力选择。会话级费用、模型排行、缓存命中率、套餐额度聚合、预算提醒都在里面；先只配你真正在用的那几家账号。
  2. dsh-whale-widget —— 只想看余额时的轻量替代：右下角挂一个小鲸鱼，不占主界面。不适合要做月度归因的人。

可以跳过

  • 只用单一订阅、且平台自带账单页面 —— 多装一个会重复采集

权限与冲突注意

  • 查订阅额度通常要各家 Cookie / API key / AK-SK，别为了"看得全"把所有账号都填进去
  • API 费用与 Plan 等值费用分开统计，数字准不准取决于你的配置，别直接拿去报销
  • 历史记录会占本地存储，确认保留范围

场景三 · 记忆管理：让下一次会话不用重新自我介绍

长期在同一个项目上和 Agent 协作，受够了每次会话都从零开始；但也不想把所有内容塞进一个记忆库。

装什么、按什么顺序

  1. dsh-mnemon —— 结构最讲究的一个：工作记忆 / 项目档案 / 长期证据分层，按问题需要检索；默认本地存储，也能接第三方 Provider。第一周先用默认配置。
  2. meow-memory / dsh-fish-memory —— 工程化偏好选 meow-memory（七层 SQLite + 反思折叠）；只想记事实、要轻量选 dsh-fish-memory。

可以跳过

  • 项目里已经有 AGENTS.md 且规则不多 —— 先写好约定文件，不够再上记忆插件

权限与冲突注意

  • 自动写入的记忆一旦写错会被反复引用，定期抽查删除
  • 接入第三方 Provider 意味着项目内容离开本机
  • 配置项很多，第一天上手容易配出自己也看不懂的组合
